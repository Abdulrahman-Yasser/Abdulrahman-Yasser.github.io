Week 22 · GSoC 2026 · AGL

Down to Three Changes on a Clean Master, and a Leaner App Repo

Oct 20 – Oct 26, 2026 Abdulrahman

This week

  • Rebuilt from a fresh AGL master. Its ivi-homescreen update fixed the activation and agl_shell problems, so the --shell xdg drop-in, the toml and activate-by-default are all gone
  • What's left: the libcamera fork, the compositor PACKAGECONFIG (now raspberrypi5 only), and the app recipe. Tested on the Pi 5: homescreen, app, calibration and live cameras
  • Removed the unused car icon and with it the only git submodule, switched the recipe to plain git://, and renamed the repo to flutter-surround-view

Details

Starting again from master

Last week ended with AGL master moving to embedder v3 and Flutter 3.47.5. This week the ivi-homescreen update landed (32117), and with it agl_shell is only bound by the background app. That was the reason the app needed --shell xdg and the activation workaround, so I dropped my old branches, synced a clean tree and added my changes back one by one, keeping only the libcamera fork as it was.

Two things came back. The cameras need the Raspberry Pi libcamera fork, and the camera tabs need flutter-auto built with the compositor PACKAGECONFIG. Without it the calibration tab still works (it draws CPU images), but every live view fails: 

register_factory('views/bev-view') failed: -4
MissingPluginException(No implementation found for method create on channel flutter/platform_views)

The compositor build is the path where ivi-homescreen stacks Flutter's layers and platform views itself, and only that path registers platform views. For now I enable it only on raspberrypi5, the board I tested: 

PACKAGECONFIG:append:raspberrypi5 = " compositor"

A leaner app repo

The only submodule was stb_image, used to load a car icon PNG. The Surround View app never set one, so I removed the car icon and the submodule (PR #6). The recipe is now plain git:// with the default destsuffix and S: 

SRC_URI = "git://github.com/Abdulrahman-Yasser/flutter-surround-view.git;protocol=https;branch=main"
SRCREV = "9fc2496729fb21e1b2613a9e6066f27f4d525d6f"

For the name, I thought about splitting the repo, since it holds three parts: the Flutter UI, the bev_view camera plugin (libcamera dmabuf into the GPU and into Flutter) and the bev_calib calibration plugin. They share the config code and change together, and one repo keeps the Yocto build to a single fetch, so I kept it whole and renamed it to flutter-surround-view, the name of the product, matching the recipe.
