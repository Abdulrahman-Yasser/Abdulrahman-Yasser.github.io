Going Upstream: Six Changes on Gerrit, and a Fix for the Activation Race

Oct 13 – Oct 19, 2026 Abdulrahman

This week

  • Built the final image from the clean AGL tree and confirmed on the Pi 5 that everything works: homescreen, the app, platform views and both IMX219s
  • Pushed the changes to AGL's Gerrit as six reviews under one topic, surround-view-flutter-v3, with a note that they need meta-flutter v3
  • Went through the reviews: two homescreen changes abandoned because Scott fixes them at the source, and the activate-by-default workaround rejected
  • Wrote a fix for the activation race in agl-compositor itself, tested it on the Pi 5 with the workaround off, and pushed it as a seventh review, which turned out to be the wrong place to fix, it should be in the shell
  • AGL master moved to meta-flutter's embedder v3 and Flutter 3.47.5, so I set my old workarounds aside and started again from plain master with only my app

The two abandoned changes were the right symptoms with a better fix one level down. The black screen is a good example: I made the homescreen ask for the background role on its command line, but it already asks for it in its configuration file, and v3 had silently stopped reading that setting.

Scott's question on 32099: why --shell xdg?

The xdg shell stuff confuses me a bit? The systemd unit generated by flutter-app.bbclass does not specify the shell, it only passes xdg-shell-app-id. 
[AglShell] agl_shell already in use by another client
[Display] shell 'agl' handshake failed

Without --shell, the v3 embedder binds agl_shell, which only the homescreen may hold, so the app exits with the error above. --shell xdg runs it as a plain app window.
